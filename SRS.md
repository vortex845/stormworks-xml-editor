## 1. Introduction (Введение)

### 1.1 Purpose (Назначение)
Целью данного документа является определение требований к десктопному приложению для ОС Windows, предназначенному для просмотра и редактирования файлов построек (vehicles) игры *Stormworks*. Приложение позволяет пользователям изменять параметры объектов без необходимости запуска игры или ручного редактирования XML-кода.

### 1.2 Scope (Границы проекта)
Разрабатываемое ПО представляет собой автономное приложение (Standalone Application).
*   Входит в границы проекта: Парсинг XML-файлов Stormworks, визуализация структуры постройки (список), редактирование компонентов (поворот, изменение размера текстур объектов), сохранение изменений обратно в XML.
*   Не входит в границы проекта: 3D-рендеринг постройки в реальном времени, синхронизация с игрой по сети, создание новых компонентов с нуля (только на основе существующих ID игры).

### 1.3 Definitions, Acronyms, and Abbreviations (Определения)
*   SRS: Software Requirements Specification.
*   XML: Extensible Markup Language — формат файлов сохранений игры.
*   Component: Игровой блок или деталь.
*   GUI: Graphical User Interface — графический пользовательский интерфейс

## 2. Overall Description (Общее описание)

### 2.1 Product Perspective (Перспектива продукта)
Приложение является вспомогательным инструментом (третья сторона) для игры *Stormworks*. Оно решает проблему неудобства ручного редактирования XML-файлов, которые имеют сложную структуру и высокую вложенность. Приложение выступает в роли "просмотрщика и редактора свойств".

### 2.2 Product Functions (Основные функции)
*   Открытие и валидация XML-файлов сохранений Stormworks.
*   Отображение иерархической структуры постройки (Components).
*   Поиск и фильтрация компонентов по типу или ID.
*   Редактирование свойств выбранных компонентов (поворот, изменение размера текстур объектов).
*   Экспорт измененных данных в валидный XML-файл.

### 2.3 User Characteristics (Характеристики пользователей)
Целевой пользователь — игрок в *Stormworks*, знакомый с основами механики игры, но не обязательно являющийся программистом. Пользователь ожидает интуитивный GUI.

### 2.4 Constraints (Ограничения)
*   ОС: Microsoft Windows 10/11.
*   Среда разработки: Язык программирования C++ (Qt).
*   Формат данных: Строгое соответствие схеме XML игры Stormworks.

### 2.5 Assumptions and Dependencies (Допущения и зависимости)
*   Формат XML-файлов игры не изменится критически в ближайших обновлениях.
*   Пользователь имеет установленную игру для тестирования результатов редактирования.

## 3. Specific Requirements (Специфические требования)

### 3.1 External Interfaces (Внешние интерфейсы)
*   User Interface: Графический интерфейс Windows (окна, панели инструментов, древовидные списки, поля ввода).
*   Software Interface: Файловая система Windows (чтение/запись .xml).
*   Hardware Interface: Не требуется специфического оборудования (работает на стандартном ПК).

### 3.2 Functional Requirements (Функциональные требования)
*   Загрузка файла. Система должна позволять пользователю выбирать XML-файл постройки через диалоговое окно.
*   Парсинг. Система должна считывать данные о компонентах, игнорируя неизвестные теги без вылета.
*   Визуализация. Система должна отображать список компонентов с возможностью сортировки по ID и названию.
*   Редактирование свойств. При выборе компонента система должна отображать его текущие параметры (например, x, y, z) в полях ввода.
*   Валидация ввода. При изменении параметров система должна проверять их на соответствие допустимым диапазонам. Дополнительно: Система должна предупреждать пользователя, если ID блока не найден в базе данных игры.
*   Сохранение. Система должна сохранять изменения в файл, сохраняя структуру оригинального XML (порядок тегов, атрибуты).

### 3.3 Quality of Service (Нефункциональные требования)
*   Производительность: Открытие файла размером до 50 МБ должно занимать не более 3 секунд.
*   Надежность: Приложение не должно повреждать исходный файл при ошибке сохранения.
*   Локализация: Интерфейс должен быть на русском языке (или английском, в зависимости от локализации).
*   Безопасность: Приложение не должно передавать данные в интернет.

### 3.4 Design Constraints (Ограничения проектирования)
*   Приложение должно использовать нативные библиотеки Windows для обеспечения высокой скорости работы.
